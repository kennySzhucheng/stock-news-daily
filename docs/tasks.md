## M1 新闻收集模块

**职责：** 从多个来源抓取最近 24h 新闻原文，输出统一 JSON 格式。

**要求：**
1. 多元化来源（见 sources.md），每类至少一个源
2. 每条新闻统一结构：`{time, source, url, category_hint, text}`
3. 跨源去重（同一事件保留最早/最权威一条）
4. 失败的来源跳过并在输出中标记，不阻塞整体
5. 请求间隔 ≥0.5s，带 User-Agent，不做高频抓取

**输出文件：** `data/raw_news.json`

**验收：** 本地运行能产出 ≥50 条/天的新闻，含至少 3 个不同类别来源

## M2 新闻筛选与结构化模块

**职责：** 用免费模型（GLM-4-Flash）把原始新闻变成结构化清单。

**要求：**
1. 分类：宏观政策 / 行业动态 / 个股公告 / 国际市场 / 其他
2. 对每条提取：涉及板块、涉及个股（名称+可辨识代码）、情绪倾向（利好/利空/中性）
3. **交叉验证打标**：与其他源报道同一事件的 → `已确认`，否则 → `单源待核实`
4. 丢弃与股市无关的纯社会新闻（但保留宏观政策类即使看似间接）
5. 单源待核实的条目在后续所有展示中必须保留该标记

**输出文件：** `data/structured_news.json`

**验收：** 对一天数据跑完后，分类准确率人工抽查 ≥80%，确认/待核实标记正确

## M3 AI 深度分析模块

**职责：** 用 DeepSeek 对结构化新闻做综合分析。

**要求（prompt 硬约束）：**
1. 只允许基于输入的新闻原文分析，禁止编造未提供的消息 → 在 prompt 中明确"你不知道的不要写"
2. 输出结构固定：
   - 今日市场情绪概览（一段话 + 乐观/中性与谨慎的判断）
   - 值得关注的板块（2-4 个，说明逻辑链：哪条新闻 → 为什么可能与股价相关）
   - 涉及个股清单（仅列出新闻中出现的，附"新闻关联点"与"不确定性说明"）
   - 风险提示（至少 2 条，含"新闻≠股价"的常规提醒）
3. 所有判断句附置信度（高/中/低）
4. 输出中不得出现"建议买入/卖出"字样，只允许"值得观察""建议持续跟踪"等中性表述

**输出文件：** `data/analysis.md`

**验收：** 人工检查输出无编造内容（随机抽 3 条论断能在原始新闻中找到出处）

## M4 行情数据模块

**职责：** 抓取 M2 提取出的个股的当日行情，作为"新闻 vs 价格位置"的佐证。

**要求：**
1. 东方财富公开接口（已验证：`push2.eastmoney.com/api/qt/stock/get`）
2. 输入个股票代码列表（需自动推断沪深市场前缀：600→1.，000→0.，300→0.，003→0. 等）
3. 输出：名称、现价、今日涨跌幅、可加逻辑：5日涨跌幅
4. 接口失败静默跳过该个股

**输出文件：** `data/quotes.json`

**验收：** 任选 5 只含沪、深、创业板的股票代码，行情数据正确（与行情软件对照）

## M9 交互式网页版（本地服务 + 静态导出）✅

**职责：** 补齐推送版做不到的能力——检索、聚合、追问。
推送版是"读一遍就走"的长文，M9 面向"我想自己找"的场景。

**要求：**
1. 同一套前端跑两种数据源：本地服务（`/api/*`）与静态导出（`./api/*.json`）
2. 只依赖 Python 标准库，不需要 pip 安装任何东西
3. 数据更新后刷新页面即可，服务不重启也能拿到新数据
4. 分析正文里的引用编号 `[12]` 可点击跳转到出处新闻

**功能（均多于推送版）：**
- [x] 总览：情绪仪表（含基数说明）、统计卡、多空分布、分类分布、数据源状态、涨跌榜、热门板块
- [x] 新闻：全文搜索（空格分隔为 AND）+ 分类/情绪/来源数/来源/板块/个股 六维筛选 + 三种排序 + 分页
- [x] 原始新闻视图：可查看被 M2 过滤掉的 1000+ 条，并标明是否被选中
- [x] 详情弹层：全文 + 元信息 + 相关行情 + 同板块同个股的关联新闻（可继续跳转）
- [x] 行情：可点表头排序的表格，含未取到行情的个股说明
- [x] 板块：按新闻数排序的板块卡，带多空分布条与关联个股
- [x] 深度分析：M3 全文（引用可点击）+ **AI 追问**
- [x] 历史：按日期列出盘前/盘后，可直接打开对应日报
- [x] 静态导出随日报一起部署到 Pages（`/web/`）
- [x] `sync.py`：把云端每天的最新产出拉到本地，本地不必重跑流水线
      也能看到当天内容；`server.py --source auto|local|export` 选择数据来源

4. **新闻不足以回答时必须明说**，并指出还缺哪类信息，不得用模型自身知识补位
5. 检索按关键词打分挑相关新闻，用户勾选的新闻必进上下文

## M10 候选观察清单 + 事后复盘 ✅

**职责：** 把 M3 每天给出的判断变成**可检验的记录**。
在此之前，日报每天说"这几只值得关注"，但**从来没有人回头看它说对了没有**。
M10 在记录当天锁下基准价，之后按 T+1/T+3/T+5 回填它相对沪深300 的真实超额，
**含跑输的**，长期公开。

**要求：**
1. 候选必须**带可观测的推翻条件**。`invalidation` 为空或不足 8 字的条目**在代码里被丢弃**，
   不靠 prompt 措辞约束 —— 让"不构成投资建议"有结构支撑，而不是一句免责声明
2. 只能从**已有材料**里选（M3 的分析 + 当日新闻 + 当日行情），不得引入材料外的标的
3. 全文不出现"建议买入/卖出"，**不给"胜率""命中率"**；均值必须与样本数同时出现
4. 候选解析不到行情时**仍记账但 `secid: null`**，不打分，UI 如实标注，不静默丢弃

**关键设计（三条结构性保障，缺一不可）：**

| 保障 | 不做会怎样 |
|---|---|
| **收盘闸门** `close_ready()` | 判据是**报价自带的时刻**（腾讯源的 `[30]` 字段），不是"现在几点"。缺了它，盘前 08:10 那次运行会拿**昨天的收盘价**去比昨天的基准价，把 T+1 写成 0%，而账本**一写就不再改** |
| **到期即补、逐档独立** `score_pending()` | 每档 `k` 各自判逾期，不是取 `min(due)`。否则一条 T+1 逾期 8 天的旧记录会**顺带把刚到期、完全正常的 T+5 也标成过期** |
| **板块代码表落盘缓存** `reports/picks/boards.json` | 板块名单接口失败时若直接 `secid=None` 记账，这条候选就**永久**打不了分（账本不重算）。改成失败回退缓存、成功则合并 |

**持久化（不改 `.gitignore`、不加 git 步骤）：** 账本写 `reports/picks/ledger.jsonl`。
`daily.yml` 部署时 `publish_dir: ./reports`，即 gh-pages 分支根 == 仓库 `reports/`；
工作流开头那步"恢复历史日报"会还原**整棵** gh-pages 树。于是账本免费获得跨天闭环：
开机还原 → 追加/打分 → 部署推回。所有对 `reports/` 的 glob 都是非递归 `*.html`，
`picks/` 子目录不会污染索引页。

**输出文件：**
- `reports/picks/ledger.jsonl` — 一行一个候选，含基准价、`bench_level`、`reviews{1,3,5}`
- 三处展示：M5 日报版块（`#picks`，夹在 `#market` 与 `#quotes` 之间）/ M6 微信推送块 /
  M9 网页版「候选」标签页

**已知局限（明说，不掩盖）：** 收益率是**未复权**口径，除权除息期间会把分红当成下跌，
污染超额。账本里保留了 `base_price` 与 `base_prev_close` 两个原始值，将来要补复权有数据可用。

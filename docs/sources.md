## 五、交叉验证规则

- 同一事件（AI 判断或标题相似度）被 **≥2 个独立来源**报道 → `已确认`
- 仅单源 → `单源待核实`，在日报中永久保留该标记
- 政策类新闻：若与政府官网原文一致 → 可升级为最高置信
- 注意"转载不算独立源"：转载与原发需判别，只有独立采访/独立发布才算第二源

### 巨潮：两个静默的坑（都已在代码里设防）

1. **类目码无效不报错，而是静默回退成「全部公告」**（约 1400 条/天）。

## 八、2026-10-04 测活：两个「官方源」其实是死的

做数据质量改造时顺手实测了每个 RSS 源的真实内容，结果与 09-16 那次"全部可用"的结论
**不矛盾但完全不同层面**：接口可达 ≠ 有当日内容。当时的"300 条/天""100 条/天"只是
**抓到多少条**，而不是**多少条进了日报**。

| 源 | 实测内容 | 判定 |
|---|---|---|
| 36氪 | 30 条，时间落在最近几天（`2026-09-29 ~ 10-04`） | ✅ 正常 |
| **新华网时政** | feed **整体冻结在 2022-12-09 ~ 12-14**；item **没有 `<pubDate>`**，时间写在 `</link>` 之后的裸文本里（`</link>Wed,14-Dec-2022 11:37:37 GMT<description>`，300/300 条都是这个形态） | ❌ 死源 |
| **人民网时政** | item 时间只有日期（`2025-06-05`），**最新停在 2025-06** | ❌ 死源 |
| 中国政府网政策库 | 两页共 40 条，发布日期 `2026-05-29 ~ 2026-09-30`，**10-01~10-04 一条没有** | ⚠️ 活着但不是每天有 |

### 为什么以前没发现

1. **时间解析失败 → `time=""` → 排序垫底 → 被 150 条上限截掉**，所以这 390 条
   「官方综合」**从来没有一条真正进过日报**；旧代码也不报错，于是它一直表现为
   "每天抓到 390 条"，而 M2 的 `official` 类目存活数其实长期是 **0**。
2. 更糟的是这些**旧闻还参与竞争**：空时间条目在按时间倒序的队列里排到最后，
   看起来"不影响"，但每日统计里的"1115 条"是虚的。

### 2026-10-04 的处置

- **不再静默**：`_parse_ts` 补齐常见格式（含新华网那种裸文本、人民网的纯日期），
  解析不出来的条目**显式丢弃并打 warn**；早于窗口的条目也打 warn 计数。
- **不再虚报**：`collect()` 剔除 `time=""` 的条目，并在 status 里记
  `dropped_no_time`，M1 的日志因此能如实反映"抓了多少、留了多少"。
- **两个死源保留在列表里**（万一复活就能自动吃回来），但**不要指望它们供给内容** ——
  它们的角色从"白抓 400 条"变成"一个请求 + 一行 warn"。
- **政策源给 7 天窗**（`SOURCES` 第 4 项）：政策文件不是每天都有，按 24 小时过滤会让
  「政府发布」这个类目在绝大多数日子直接归零。7 天窗既保住了类目，又不会再像旧实现那样
  把**几个月前**的国函国令当"今日政策"塞进 digest（下游每条都带原始时间戳，日期是可见的）。

> **处置（2026-10-04 晚定）**：用户明确要求**保留新华网与人民网**（宁可留着等它们复活，
> 也不移除），所以它们继续留在 `SOURCES` 里；**通用新闻的供给改由新增的活源承担**（见第九节）。
> 另外 README 第四节把「政府发布」写成「发改委、央行、证监会官网」，但 `SOURCES` 里
> **只有** `中国政府网` 一个 —— 文档比实现乐观，已更正。

### 顺带修掉：巨潮的"非交易日被当成故障"

旧实现里区间内 0 条公告会 `raise RuntimeError("巨潮基线查询为空")` —— 于是每个周末与
长假都报一条"故障"，与真故障长同一张脸。现在区分两种情况：**响应体拿不到 = 接口不通
（仍报错）**；**拿到响应但 totalRecordNum=0 = 区间内本来就没有公告（打一行 warn，
按 0 条返回）**。探活时的实际输出：

```
[warn] 巨潮 2026-10-03~2026-10-04 区间内没有公告（周末/长假属正常），本源于 0 条
```
